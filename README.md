# OCTAGO · Chain Reaction

8×8 카드 필드에서 화살표 연결·아이템·재생성을 이용하는 싱글플레이 퍼즐 프로토타입입니다. 기존 회전 모양은 비활성화되어 있으며, 카드 중앙에는 장착 아이템이나 보급 표시를 보여줍니다. 카드는 첫 발동에 즉시 파괴됩니다.

## 실행

타이틀 화면·게임·기록 서버를 함께 실행합니다. Node.js 18 이상이 필요하며 실행용 외부 패키지는 없습니다. 웹 폰트를 불러오지 못해도 시스템 폰트로 작동합니다. 서버 랭킹을 사용하려면 HTML 파일을 직접 열지 말고 아래 서버 주소로 접속하세요.

로컬 서버로 실행하려면 Node.js 18 이상에서:

```powershell
node server.cjs
```

http://localhost:3000 접속. 다른 포트는 `$env:PORT=3001`로 지정합니다.

Railway 공용 서버 배포용 `Dockerfile`과 `railway.json`, 소스 패키징 명령을 포함합니다. 영구 볼륨 연결과 배포 절차는 [Railway 배포 안내](docs/deploy-railway.md)를 참고하세요.

## 타이틀·결과·서버 기록

- 타이틀에서 플레이어 이름(최대 16자)을 입력하고 게임을 시작합니다. 서버 랭킹과 브라우저에 저장된 최고 점수·최고 도달 스테이지를 확인할 수 있습니다. 진행 중 타이틀로 돌아가면 게임이 멈추며 이어하기로 돌아갈 수 있습니다.
- 게임오버 후 모달 결과창에 점수·도달 스테이지·파괴 수·최대 연쇄·서버 등수를 표시하고 자동 저장합니다. 저장 실패 시 다시 시도할 수 있습니다. 결과창에서 새 게임, 타이틀, 직전 발동 되돌리기를 선택할 수 있습니다.
- 랭킹은 점수 내림차순, 동점이면 도달 스테이지 내림차순입니다. 두 값이 모두 같으면 같은 등수(예: 1·1·3위)로 처리합니다. 상위 10개 기록을 표시하며, 플레이어별 최고 기록이 아닌 종료한 게임별 기록입니다.
- 서버는 클라이언트가 보낸 점수를 신뢰하지 않고 시드·카드 발동·아이템 장착 내역을 `engine.js`로 재생해 점수와 스테이지를 계산합니다. 종료하지 않은 게임이나 규칙에 어긋난 내역은 저장하지 않습니다.
- 기록은 첫 저장 시 `data/leaderboard.json`에 영구 보관하며 서버를 재시작해도 유지됩니다. `LEADERBOARD_FILE` 환경변수로 저장 파일을 바꿀 수 있습니다. 호스팅할 경우 이 파일을 영구 볼륨에 두세요. 서버는 공개용 HTML·JS·CSS와 API만 제공하며 기록 원본과 서버 소스는 웹으로 제공하지 않습니다.
- 같은 판은 저장 재시도나 되돌리기 후 재종료해도 하나의 기록으로 갱신합니다. 이미 완료된 기록은 다음 종료 기록이 저장될 때까지 유지됩니다. 게임마다 별도 저장 키를 사용하고 오래된 요청이 새 기록을 덮어쓰지 않도록 버전을 확인합니다.
- API: `GET /api/health`, `GET /api/leaderboard?limit=10`, `POST /api/scores`. POST는 `runId`, `token`, `revision`, `name`, `seed`, `actions`를 받으며 각 action은 `{type:'activate',index}` 또는 `{type:'equip',slot,index}`입니다.
- 서버는 기본적으로 `0.0.0.0:3000`에서 실행되어 다른 기기의 연결도 받습니다. 이 PC에서만 사용하려면 `HOST=127.0.0.1`로 제한할 수 있습니다.

## PC·모바일 공통 랭킹

랭킹은 접속한 기기나 브라우저에 관계없이 **같은 API 서버**의 기록을 사용합니다. 플레이어 이름과 개인 최고 기록은 기존처럼 기기별 브라우저에 저장되며, 서버 랭킹과 구분됩니다.

### 같은 네트워크에서 바로 사용

`node server.cjs`를 실행하면 `Network http://192.168.x.x:3000`처럼 실제 네트워크 주소가 표시됩니다. 같은 Wi-Fi에 연결된 PC·모바일에서 그 주소로 접속하세요. 각 기기의 `localhost`는 서로 다른 기기를 뜻하므로 공유 주소로 사용할 수 없습니다. 기기 간 접속에는 서버 PC의 방화벽에서 Node 또는 TCP 3000 포트가 허용되어 있어야 합니다.

게임과 API를 함께 제공하므로 이 구성에서는 별도 설정이나 CORS가 필요하지 않습니다. LAN의 일반 HTTP 주소에서는 `crypto.randomUUID`가 없어도 안전한 난수로 UUID를 생성하므로 게임 시작과 기록 저장이 가능합니다.

### 서로 다른 도메인이나 앱에서 사용

인터넷과 다른 네트워크의 기기까지 연결하려면 공용 HTTPS 서버에 이 Node 서버를 배포하고 영구 저장 경로를 설정합니다. 모든 클라이언트가 그 서버를 바라보도록 구성하세요. 이 저장 방식은 하나의 API 서버 인스턴스를 기준으로 하며, 여러 독립 서버를 띄우면 기록이 자동 통합되지 않습니다.

예를 들어 랭킹 API를 `https://rank.example.com`, 게임을 `https://play.example.com`에 배포할 경우 API 서버에서는:

```powershell
$env:HOST='0.0.0.0'
$env:PORT='3000'
$env:LEADERBOARD_FILE='/persistent/octago/leaderboard.json' # 호스팅 환경의 실제 영구 저장 경로
$env:CORS_ORIGINS='https://play.example.com,capacitor://localhost,http://localhost'
node server.cjs
```

게임을 제공하는 Node 서버에서는:

```powershell
$env:RANKING_API_URL='https://rank.example.com'
node server.cjs
```

`RANKING_API_URL`은 공개 클라이언트 설정인 `/config.js`에 반영됩니다. HTML·JS를 CDN이나 앱 WebView로 묶는 경우에는 [config.js](config.js)의 `apiBaseUrl`을 같은 공용 API 주소로 지정하고 `platform.js`도 함께 포함하세요. 기본값이 빈 문자열이면 게임을 제공하는 서버의 `/api`를 사용합니다. 주소에는 인증 정보·쿼리·해시를 포함하지 않습니다.

`CORS_ORIGINS`에는 실제 게임 웹 주소나 앱 WebView의 Origin을 쉼표로 구분해 등록합니다. `capacitor://localhost`는 설정 예시이며 앱이 보내는 실제 Origin을 사용하세요. Origin이 `null`인 WebView는 필요한 경우 `null`을 명시합니다. 공개 랭킹 API를 모든 웹 클라이언트에 제공하려면 `*`를 명시할 수 있습니다. 기본값은 동일 출처만 허용하며, 다른 출처의 JSON POST 사전 요청(`OPTIONS`)을 지원합니다. 네이티브 HTTP 클라이언트는 기존 JSON API를 그대로 사용할 수 있습니다.

기록 저장은 플랫폼 공통 시드와 발동·아이템 사용 내역을 전송하며 서버가 검증합니다. 서버 파일에 저장하므로 기기를 바꾸거나 브라우저 저장소를 지워도 서버 기록은 유지됩니다. 현재 저장소에는 외부 호스팅 계정이나 공용 HTTPS 주소가 설정되어 있지 않으며, 위 주소들은 배포 설정 예시입니다.

## 게임 규칙

- 필드는 8×8이며, 카드는 상하좌우·대각선의 8방향 중 5~8곳에 화살표가 생깁니다. 5·6·7·8방향의 등장 확률은 각각 25%이며, 중복 없이 무작위 위치를 고릅니다. 안·밖 방향은 무작위로 정하되 안쪽·바깥쪽이 각각 최소 1개씩 있어야 합니다. 하나만 반대인 조합도 허용합니다. 초기 필드·대기열·새 카드에 같은 규칙을 적용합니다.
- 화살표는 크고 납작한 삼각형이며 바깥은 파랑, 안쪽은 연한 빨강입니다. 카드 전체 배경은 안·밖 비율에 따라 정한 하나의 단색입니다. 바깥이 많으면 파랑, 안쪽이 많으면 노랑이 진해집니다. 기존 회전용 중앙 모양과 회전은 비활성화되어 있습니다.
- 클릭한 일반 카드는 첫 페이즈에 발동합니다. 바깥 화살표가 이웃 카드의 정확히 마주 보는 안쪽 화살표와 맞으면 다음 페이즈에 연쇄 발동합니다. 같은 페이즈에 여러 신호를 받아도 한 번만 발동합니다.
- 남은 발동 횟수는 3회로 시작하며, 플레이어가 일반 카드를 선택해 발동할 때 1회 차감합니다. 일반 연쇄 발동과 아이템 장착에는 추가 비용이 없으며, `+1`과 `−1` 카드가 횟수를 조정합니다. 연쇄 중에는 음수가 될 수도 있지만 전체 연쇄와 재생성까지 마친 뒤 0 이하이면 게임오버가 됩니다. 게임오버 횟수는 0으로 표시하며 새 게임 또는 직전 발동 되돌리기가 가능합니다.
- 첫 스테이지부터 서로 다른 카드에 초록색 `+1` 3개, 노란색 `?` 1개, 빨간색 `−1` 2개를 배치합니다. 스테이지는 카드 한 장을 선택해 시작한 전체 연쇄를 뜻합니다. 연쇄 종료 후 게임이 계속되면 발동 여부와 관계없이 여섯 스테이지용 특수 표시를 모두 다시 배치합니다. 대기열에서 생성된 청록색 `?`는 이 재배치에서 제외합니다.
- `+1`·`?`·`−1` 특수 카드는 연쇄 전용입니다. 직접 클릭·터치·Enter/Space로 발동할 수 없고 일반 카드의 화살표 또는 아이템 효과로만 연쇄 발동합니다. 잠금 아이콘과 점선 테두리로 표시하며 인스펙터와 안내 문구에도 직접 선택 불가를 표시합니다. 특수 카드에도 아이템을 장착할 수 있지만 직접 발동 제한은 유지됩니다.
- `+1` 카드를 연쇄로 발동하면 남은 발동 횟수를 1회 회복합니다. 같은 페이즈에 세 장이 발동하면 총 3회를 회복하며, 마지막 발동의 연쇄에서 회복해 게임을 이어갈 수도 있습니다.
- `−1` 카드는 연쇄로 발동하면 남은 횟수를 1 줄입니다. 같은 페이즈의 회복과 감소는 합산되며 카드 처리 순서에 영향을 받지 않습니다. 연쇄 중 0 이하가 되어도 이후 `+1` 회복까지 모두 처리한 뒤 게임오버를 판정합니다.
- 스테이지 종료 시 남은 스테이지용 특수 표시를 지우며 바탕 카드의 화살표와 장착 아이템은 유지합니다. 청록색 `?`는 카드 자체와 위치·화살표·장착 아이템을 그대로 유지합니다. 특수 표시는 서로 겹치지 않고, 빈 위치가 충분하면 같은 종류의 직전 위치를 피해서 배치합니다. 재배치 자체로 아이템이나 발동 횟수를 획득·차감하지 않습니다.
- 초기 대기열과 자동 충전되는 대기 카드에는 각각 3% 확률로 청록색 `?`가 생성됩니다. 초기 필드에는 생성하지 않으며, 대기열에서 FIFO 순서로 필드에 들어온 뒤 발동 전까지 같은 자리에 유지됩니다. 매 스테이지의 노란색 `?` 1장과 별도로 추가되며 난이도 배치의 기준에도 포함하지 않습니다. 청록색 아이콘과 테두리, 인스펙터의 보존 안내로 구분합니다. 확률은 `engine.js`의 `QUEUE_MYSTERY_CHANCE`에서 조절할 수 있습니다.
- `−1` 한 장은 다른 특수 카드보다 먼저 배치하며 난이도와 보상 카드와의 거리에 관계없이 후보 칸에서 균등 무작위로 뽑습니다. 다른 한 장은 난이도에 따른 거리 가중치를 적용합니다. 인스펙터에서 두 배치 방식을 확인할 수 있습니다.
- 배치 난이도는 1~20스테이지 동안 선형으로 높아지고 이후 최대 난이도를 유지합니다. 8방향 이동 거리를 기준으로 초반에는 `+1`과 `?`를 가깝게, 난이도 적용 `−1`을 보상 카드에서 멀리 배치합니다. 후반에는 `+1`과 `?`의 거리를 늘리고 난이도 적용 `−1`을 보상 카드 가까이에 배치합니다. 매 스테이지 새 배치에 적용되며 무작위 `−1` 한 장에는 적용하지 않습니다. `engine.js`의 `DIFFICULTY_RAMP_STAGES`에서 상승 기간을 조정할 수 있습니다.
- 아이템은 가로줄 전체·세로줄 전체·대각선을 포함한 주변 8칸의 세 종류입니다. 카드 중앙의 아이콘으로 표시되며, 카드가 발동하면 일반 화살표 신호와 함께 범위 안의 카드를 방향과 관계없이 다음 페이즈에 발동시킵니다. 다른 아이템 카드도 연쇄로 효과를 냅니다. 자기 자신과 같은 페이즈에 이미 발동한 카드는 중복 발동하지 않습니다.
- 보관함은 3칸이며 처음에는 비어 있습니다. 노란색·청록색 `?` 보급 카드를 연쇄로 발동하면 세 종류 중 무작위 아이템 하나를 얻고 해당 카드와 표시가 소모됩니다. 세 칸이 가득 차면 기존 아이템을 유지하고 추가 획득을 생략합니다. 청록색 `?`는 생성된 페이즈에도 연쇄 발동할 수 있으며 직접 클릭해서 발동할 수 없습니다. 특수 카드 배치·아이템 획득·화살표 생성·대기열의 희귀 표시 확률은 각각 별개의 시드 난수를 사용합니다.
- 연쇄를 시작하기 전 선택 턴에 아이템을 카드로 드래그해 놓으면 한 칸을 소비해 장착합니다. PC 마우스 드래그와 모바일 터치 드래그를 지원하며, 클릭이나 짧은 터치로 아이템을 선택·장착하지 않습니다. 장착은 발동을 일으키지 않습니다. 카드당 아이템은 하나이며 장착된 카드는 파괴될 때 아이템도 소모합니다. `?` 카드에도 장착할 수 있습니다. 드래그를 취소하거나 필드 밖에 놓으면 아이템을 유지하며, 연쇄 진행 중에는 장착할 수 없습니다.
- 발동 카드는 신호를 보낸 뒤 첫 발동에 바로 파괴되어 득점합니다. p페이즈에 파괴된 칸은 p+1페이즈 동안 비어 있고, p+2페이즈 시작에 대기열 카드로 채웁니다. 빈칸 숫자는 보충까지 남은 페이즈입니다.
- 오른쪽 대기열은 실제 보충될 카드를 위에서부터 보여줍니다. 보충될 위치와 페이즈가 정해지면 함께 표시합니다. 데스크톱은 다음 8장, 모바일은 다음 6장을 표시하며 사용한 만큼 계속 자동 충전합니다. 사용 후 남은 카드가 앞자리로 올라가고, 아래쪽 카드가 짧은 시차를 두고 차례로 따라 올라옵니다. 이동은 페이즈 간격의 90% 이내(최대 360ms)에 끝나며 히트스톱 중에는 함께 정지합니다.
- 같은 생성 페이즈의 빈칸은 왼쪽 위부터 오른쪽, 다음 행 순서로 보충합니다. 최대 24ms 시차의 짧은 등장 연출과 순번으로 순서를 보여주며, 전체 연출은 기본 페이즈 간격의 80% 이내(최대 240ms)에 끝납니다.
- 다음 페이즈에 재생성될 칸으로 향하는 신호는 대기열에 예정된 카드의 안쪽 면으로 판정합니다. 방향이 맞으면 새 카드도 생성된 페이즈에 발동할 수 있습니다. 더 일찍 빈칸에 보낸 신호는 저장하지 않습니다. 발동과 재생성 대기가 모두 끝나면 연쇄가 종료됩니다.
- 파괴 시 카드 색조에 맞춰 섬광·충격파·파편을 재생합니다. 기존 방사형 파편 외에 위로 튀었다가 회전하며 아래로 흩날리는 카드 조각을 추가했습니다. 연쇄가 깊어질수록 크기·비산 거리·충격파 반경·빛줄기·광량이 `1 + 0.45 × log₂(페이즈)` 배율로 커지며, 9페이즈 이후에도 범위가 커집니다.
- 파괴된 칸에는 실제 획득 점수를 0.9초간 표시하고 빠르게 사라집니다. 같은 칸에서 다시 득점하면 최신 점수로 갱신합니다. 득점 페이즈에는 0.1초 히트스톱을 적용하며, 여러 장이 동시에 파괴돼도 한 번만 멈춥니다. 점수는 정지 중에도 보이고, 수동 일시정지는 별도로 유지됩니다.
- 실제 연쇄에서는 파란 화살표가 발동 카드에서 다음 카드로 이동합니다. 다음 페이즈에 발동할 대상은 자주색 테두리·빛이 1.8초 주기로 천천히 점멸하며, 신호를 받는 안쪽 화살표도 강조합니다. 그 대상에서 이어져 다다음 페이즈에 발동할 현재 카드에는 연한 자주색 테두리를 표시합니다. 보충 카드에 의한 경로는 이 예고에서 제외하며, 다음 페이즈의 점멸 표시가 우선합니다. 이동과 점멸 연출은 히트스톱 동안 멈추며 기본 페이즈 시간은 바뀌지 않습니다.
- 애니메이션 축소 환경에서는 파편을 숨기고 정적인 파괴 표시와 점수로 대체합니다. 시각 효과는 게임 난수와 점수 판정에 영향을 주지 않습니다.
- 연쇄 도중 다른 카드를 클릭할 수 없습니다. 시간 제한은 없으며 남은 발동 횟수 안에서 점수를 얻는 모드입니다.
## 프로토타입 점수식

점수 수치는 실험용으로 정했습니다. `engine.js`의 `BASE_POINTS`와 `phaseScore`에서 조정할 수 있습니다.

```text
연쇄 배율 = 1 + (페이즈 번호 − 1) × 0.5
동시 발동 배율 = 1 + (해당 페이즈 발동 카드 수 − 1) × 0.25
파괴 1장 점수 = 반올림(100 × 연쇄 배율 × 동시 발동 배율)
페이즈 점수 = 파괴 1장 점수 × 해당 페이즈 파괴 수
```

1페이즈 단독 파괴는 100점, 2페이즈 3장 동시 발동 및 파괴는 675점입니다. 모든 발동이 곧 파괴이므로 매 발동마다 점수를 얻습니다.

## 조작 및 관찰

- 클릭 또는 Enter/Space: 일반 카드 발동
- 보관함 아이템 드래그 → 카드 위에 놓기: 장착. Esc 또는 필드 밖에 놓기로 드래그를 취소합니다.
- 방향키: 카드 포커스 이동, Tab: 필드와 컨트롤 이동
- 마우스 오버/키보드 포커스: 일반 카드에서 시작하는 현재 필드의 연쇄만 예측하고, 연결에 쓰이는 바깥·안쪽 화살표를 확대해 강조합니다. 연결 화살표는 마우스를 올리는 즉시 흰색으로 고정 표시하며, 원래 방향 색의 테두리와 광채를 유지합니다. 점멸은 없습니다. 나머지 카드와 화살표는 원래 밝기 그대로 유지하며, 카드 위에 발동 순서 숫자를 표시하지 않습니다. 붉은 테두리는 현재 카드의 파괴 예상 대상입니다. 새로 보충될 카드와 그 카드에서 이어지는 연쇄는 강조와 예상 통계에서 모두 제외합니다. 특수 카드에 직접 마우스를 올리거나 포커스하면 카드 정보와 연쇄 전용 안내만 보여주며 시작점 미리보기는 만들지 않습니다. 미리보기는 실제 필드·점수·대기열·난수 상태를 바꾸지 않습니다.
- 일시정지·계속 재생·다음 페이즈: 발동·파괴·재생성 대기를 단계별 관찰. 마지막 단계는 연쇄 마무리
- 속도 슬라이더: 페이즈 간격 0.2~1.2초
- 직전 행동 되돌리기: 직전 연쇄 또는 장착 전의 필드·대기열·보관함·보급과 보너스 표시·남은 횟수·난수 상태·점수·기록 복원. 최고 점수는 유지
- 새 필드: 시드 입력 또는 무작위 생성. 같은 시드는 같은 초기 필드를 재현
- 효과음 토글, 모바일 레이아웃, 애니메이션 축소 환경 지원

최고 점수·속도·효과음 설정은 `octago-chain-v1` 브라우저 저장소에 기록합니다. 필드와 진행 상황은 새로고침하면 초기화됩니다.

## 검증

```powershell
# 외부 패키지 없이 규칙 검증
node --test tests/*.test.cjs

# 설치된 Chrome을 사용한 데스크톱·모바일 브라우저 검증
npm.cmd ci
npm.cmd run test:ui
```

브라우저 검증은 포트 3137에서 테스트 서버를 직접 열고 종료하며 `artifacts/leaderboard-ui-*.json`의 격리된 기록 파일을 사용합니다. 공통 랭킹 검증은 별도 포트의 API·게임 서버와 저장소를 분리한 PC·모바일 브라우저 컨텍스트를 사용해 교차 출처 저장·조회를 확인합니다. 사용자 기록 파일에는 테스트 결과를 쓰지 않습니다. 화면 캡처와 실패 추적은 `test-results/`에 저장됩니다. 서버 검증에는 재시작 후 보존, 동시 저장, 재시도·갱신, 잘못된 내역 거절, 비공개 파일 차단, CORS 허용·거부와 런타임 API 주소 설정이 포함됩니다.

## 파일 구성

- `engine.js`: DOM과 분리한 시드 난수, 생성, 페이즈, 파괴, 점수, 페이즈별 재생성. `ROTATION_ENABLED=false`로 실제 회전 잠금
- `app.js`: 재생 제어, 렌더링, 인스펙터, 되돌리기, 브라우저 저장
- `lobby.js`: 타이틀·결과창·랭킹 표시와 서버 통신
- `config.js`, `platform.js`: 플랫폼 공통 API 주소와 HTTP·WebView 호환 게임 식별자 생성
- `server.cjs`, `leaderboard.cjs`: HTTP API, 플레이 내역 검증, 원자적 파일 저장과 순위 계산
- `index.html`, `style.css`: 메인 필드와 반응형 화면
- `tests/engine.test.cjs`, `tests/browser/game.spec.cjs`: 규칙 및 브라우저 검증

트리플 트라이어드 대전 구현을 새로운 연쇄 퍼즐 규칙으로 교체한 버전입니다.
